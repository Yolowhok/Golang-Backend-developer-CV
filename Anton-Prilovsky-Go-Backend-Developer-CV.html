Платформа и надёжность

  • Перевёл сессии и авторизацию поддержки с PHP-монолита на Go (zero-downtime): выкатил login-as, многослойный logout и v1-маршруты тремя последовательными релизами. После переключения — 0 ошибок 5xx, трафик (~600 logout в день) бесшовно пошёл через новые микросервисы.
  • Снизил долю 5xx в auth (~50 тыс. req/day) с 0.29% до ~0 на фоне роста трафика на 23%: отделил клиентские обрывы (499 / 504) от серверных ошибок через контекст, добавил panic recovery в gRPC. Изолировал критичные транзакции — обрыв связи не оставляет полузаписанных данных. Шторм 409-х снижен с 23% до 0.6%.
  • Нашёл причину «фантомных» Network Error при загрузке фото без воспроизведения: сопоставил логи на трёх слоях (edge Nginx HTTP/2 → внутренний Nginx → PHP) — API отдавал 200, а обрывы (408 / 499) шли от мобильных клиентов на edge. Снял подозрение на регрессию и предотвратил откат стабильного релиза.
  • Внедрил Transactional Outbox (Kafka, RabbitMQ) с at-least-once доставкой, дедупликацией и DLQ: обмен с 1С больше не теряет данные, повтор не создаёт дубль.
  • Разделил ошибки на транзитные и терминальные: сетевые сбои повторяются с backoff, а в DLQ попадают только реальные баги. Кратковременные отказы 1С перевариваются незаметно.
  • Ускорил приём пачек из 1С с ~19.5 с (129 документов) до < 1 с (5000+ документов). По спанам Tempo нашёл, что 95% времени уходит на N+1 проблему (последовательные DELETE); fan-out на горутинах только истощил бы пул соединений БД. Заменил их одним запросом на батч и перевёл приём на асинхронный контракт через S3 и очередь (Claim Check).
  • Сократил запись документа с 3–4 с до миллисекунд: нашёл полный скан ~393 тыс. строк и добавил индекс на проде без блокировки таблицы.
  • Разработал сервис realtime-чата (WebSocket, REST, брокер сообщений): решил задачу синхронизации коннектов при горизонтальном масштабировании, настроил observability (Prometheus).
